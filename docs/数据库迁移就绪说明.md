# 数据库迁移就绪说明

## 现状

- 当前数据库：SQLite，文件 `backend/data/platform.sqlite`。
- 驱动：Node.js 24 内置 `node:sqlite`，同步 API。
- 表结构：`users`、`sessions`、`catalog_items`、`submissions`、`review_logs`。
- 业务数据主要存在 `catalog_items(kind, id, payload, published)`，`payload` 是 JSON 字符串。
- 认证、投稿、审核、时间轴、人物、关系图、搜索均已跑通。
- `pnpm run build` 与 `pnpm test` 通过。

## 为什么展示前不迁移

- 展示目标是“核心只读 API 可用 + 共创闭环可演示”，SQLite 已满足。
- 迁移的真正成本不在搬数据，而在**把同步 `node:sqlite` 调用改为异步 `pg` 调用**，牵涉所有数据库访问点。
- 展示前集中迁移会拖慢进度，且一旦引入异步改造 Bug，展示风险高。
- 展示后、真实用户接入前，是迁移的最佳窗口：数据少、影响面可控。

## 迁移时要改什么

### 1. 驱动与连接

- 引入 `pg` 或 `pg-promise`。
- 新增连接池配置，读取环境变量 `PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE`。
- 保留 SQLite 实现，通过 `DB_DRIVER=sqlite|postgres` 切换，便于回滚。

### 2. 同步改异步（最大工作量）

- `node:sqlite` 的 `db.prepare(...).run()/.get()/.all()` 是同步的。
- `pg` 的 `pool.query(...)` 是异步的，所有调用点要加 `await`。
- 受影响的文件：`backend/src/db.ts`、`backend/src/app.ts`、`backend/src/backup.ts`、`backend/tests/*.test.ts`。
- 建议按模块推进：auth → submissions → catalog → 只读展示 API，每模块改完跑测试再合并。

### 3. 表结构差异

| SQLite | PostgreSQL |
|---|---|
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGSERIAL PRIMARY KEY` 或 `GENERATED ... AS IDENTITY` |
| `TEXT` 存 JSON | 可继续 `TEXT`，后续再考虑 `JSONB` |
| `INTEGER` 存布尔 | 可继续 `INTEGER`，或改 `BOOLEAN` |
| `PRAGMA` 语句 | 删除，改 `SET` / `CREATE INDEX` |
| `INSERT OR REPLACE` | `INSERT ... ON CONFLICT ... DO UPDATE` |

### 4. 数据迁移

- 用脚本导出 SQLite 各表为 JSON/CSV，再导入 PostgreSQL。
- 或使用 `pgloader` 等工具，但需先处理语法差异。
- 迁移后校验：各表行数一致、`catalog_items` 的 `(kind,id)` 唯一、`users.email` 唯一、`submissions` 状态值合法。

### 5. 中文全文搜索（最大外部依赖）

- PostgreSQL 默认分词器不支持中文。
- 需要 `zhparser` 或 `pg_jieba` 扩展。
- **迁移前必须先验证目标 PostgreSQL 环境能否安装该扩展**；部分云数据库不支持。
- 若扩展不可用，退路：应用层分词后写入 `tsvector` 列，或先用 `pg_trgm + ILIKE` 兜底。

## 当前代码为迁移做的约定

- 新接口只读 `store.catalog()` 返回值，不新增 SQL。
- 关系图 `centerId/depth`、搜索高亮、分页均为内存逻辑，不依赖数据库特性。
- 所有公开过滤复用 `store.catalog()`，迁移时只需保证该方法行为一致。
- 接口统一返回 `{code,message,data}`，迁移不改变前端契约。

## 建议迁移步骤

1. 本地搭 PostgreSQL，建库建表，导入 fixtures 验证。
2. 验证 `zhparser`/`pg_jieba` 是否可安装。
3. 新增 `DB_DRIVER` 切换和 `pg` 实现，保留 SQLite。
4. 按模块把同步调用改异步，每模块跑测试。
5. 用脚本迁数据，校验行数与唯一约束。
6. 全量回归：`pnpm test` + 手工测时间轴、人物、关系图、搜索、投稿审核。
7. 切换默认驱动为 PostgreSQL，保留 SQLite 回滚开关。
8. 更新 README 和 `.env.example`，补 PostgreSQL 启动说明。

## 风险与回滚

- 风险：异步改造遗漏导致请求挂起；中文分词扩展不可用；数据迁移漏行。
- 回滚：保留 SQLite 实现，`DB_DRIVER=sqlite` 即可切回；迁移前备份 `platform.sqlite`。
- 不在展示前迁移；迁移窗口安排在展示后、真实用户接入前。
